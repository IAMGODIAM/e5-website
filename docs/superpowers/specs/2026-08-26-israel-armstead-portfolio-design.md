## 1. Purpose

Build a canonical executive portfolio surface for Israel Lee Armstead that supports senior hiring conversations across AI transformation, Chief of Staff, strategic initiatives, partnerships, institutional innovation, and frontier-technology operations.

The page must not resemble a conventional software-engineer portfolio or a generic personal-brand site. Its purpose is to make one professional thesis obvious:

> Israel repeatedly takes ambiguous institutional problems, develops the strategy, coordinates human and AI resources, and ships systems, products, programs, campaigns, or institutions that move the problem toward execution.

The page should make AI fluency credible without misrepresenting Israel as a traditional software engineer.

## 5. Flagship Case-Study Narratives

### 5.1 IAMGODIAM / Hallways & Boardrooms

**Title:** Designing governance for AI agents that can act without removing human accountability

**Problem:** Multi-agent systems can create leverage, but autonomy without provenance, policy, trust boundaries, or institutional memory creates unacceptable organizational risk.

**Israel's role:** Founder / executive architect / product owner / organizational strategist.

**Narrative:** Hallways is the orchestration/control plane; Boardrooms is the governance layer. The system formalizes rooms, roles, agents, records, execution, policy enforcement, audit trails, and human approval boundaries.

**Evidence:** Sanitized architecture diagrams; public Hallways Command Center surface where appropriate; recreated journal exhibits; public IAMGODIAM artifacts.

**Do not expose:** private Hallways repository, `.env` files, credentials, operational endpoints, sensitive journals, internal security details.

### 5.2 E5 Form Protocol

**Title:** From one advocacy intake form to reusable agent-native infrastructure

**Problem:** Traditional forms collect data but often terminate in a silo. Mission-driven teams then manually rediscover the information, notify people, route follow-up, and rebuild the same infrastructure campaign after campaign.

**Reframe:** Treat each submission as an organizational event and agent trigger, not a dead endpoint.

**Evolution narrative:**

1. Live court-support / advocacy intake need
2. Reusable protocol abstraction
3. Event log and downstream automation
4. Agent-facing MCP operations
5. authenticated intake seam for agent infrastructure
6. migration from Base44 dependency to Cloudflare Worker + D1
7. analytics pipeline / R2 data catalog

**Key product lesson:** A one-off operational need exposed a repeatable infrastructure problem; the solution was generalized, tested, migrated, and turned into a reusable protocol.

**Evidence:** Public `e5-form-protocol` repository, architecture diagrams, selected protocol excerpts, live E5 form surfaces where safe.

### 5.3 E5 Enclave

**Title:** Building an AI-native institution rather than adding AI to a traditional one

**Narrative:** E5 uses AI-enabled research, product, communications, strategy, and execution systems as part of its operating model. The portfolio should show how mission becomes an institution through research, strategy, programs, infrastructure, partnerships, and public deployment.

**Evidence:** E5 public site, selected public programs, public GitHub repository, production architecture and QA posture.

### 5.4 Black Distress Index / FarmBlock

**Title:** Turning fragmented public data into a decision instrument and intervention framework

**Narrative:** Show the path from research question to data model, methodology, public analysis, decision instrument, and program application.

**Evidence:** public repositories, methodology, structured data outputs, live/public research where available.

### 5.5 AskJesus / Center for Unity

**Title:** Early domain-specific conversational AI product development

**Narrative:** Show the translation of a specialized source domain into a conversational product experience, linked to the broader Center for Unity / Jesus Metaverse / Discover Jesus product environment.

**Role language:** product and AI development; formative-board participant; Executive Board Member Emeritus.

## 6. Evidence Taxonomy

Every portfolio artifact must carry one or more explicit tags:

- **LIVE** — working public product
- **PUBLIC SOURCE** — public GitHub evidence
- **CASE STUDY** — sanitized internal system
- **RESEARCH** — methodology, data, or publication
- **INSTITUTIONAL** — deployed organizational infrastructure

This avoids blurring production, prototype, research, and private systems.

## 7. Security and Sanitization Rules

1. Never link the private `hallways-boardroom` repository.
2. Never embed raw private journal files.
3. Never expose environment files, credentials, tokens, operational endpoints, internal IP addresses, private relay URLs, or secret-storage locations.
4. Recreate journal excerpts as portfolio artifacts using only the minimum facts necessary to communicate the operating lesson.
5. Avoid publishing implementation details that increase attack surface for active E5 infrastructure.
6. Public GitHub artifacts must be reviewed for accidental secrets or operationally sensitive content before direct linking.
7. Product links may be removed from the public card grid if the live destination is not production-ready at launch time.

## 8. Technical Architecture

### Route

Create:

`public/work/israel-armstead/index.html`

### Supporting assets

Prefer a small, route-local asset package:

- `public/work/israel-armstead/portfolio.css`
- `public/work/israel-armstead/portfolio.js`
- `public/work/israel-armstead/assets/` for diagrams or optimized images if needed

Do not add a framework dependency for this page.

### Behavior

- semantic HTML is complete without JavaScript
- JavaScript only enhances navigation, evidence filtering, reveal choreography, or diagrams
- no content may require WebGL
- reduced-motion path must remain authored and complete
- no scroll-jacking
- no forced intro sequence
- internal page navigation should remain usable with JS disabled

### External links

Open external products and GitHub in new tabs with `rel="noopener noreferrer"`.

### Resume

If the résumé PDF is not yet committed to a public E5 path, the initial implementation should include a clearly styled disabled/coming-soon resume action rather than a broken link. Replace only after a verified public asset exists.
